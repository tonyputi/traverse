# ADR 0001: V0.1 architecture and public contracts

## Status

Accepted — 2026-08-27.

## Context

Traverse gives Laravel applications and AI agents provider-independent, AI-native access to web content. Lightpanda is the first planned driver, but it must not define the public abstraction.

Before this decision, we reviewed Laravel 12's manager implementation and current first-party package patterns from Socialite, Scout, Sanctum, Horizon, Pulse, Reverb, Laravel AI, and Laravel MCP. The package must feel Laravel-native while avoiding generic browser automation, provider coupling, and speculative APIs.

## Decision

### Manager and driver resolution

`BrowserManager` extends `Illuminate\Support\Manager` and implements the package `Contracts\Factory` contract. The factory exposes one method:

```php
public function browser(?string $driver = null): Browser;
```

`browser()` delegates to the framework's memoized `driver()` resolution. Built-in creators use the inherited `create{Studly}Driver()` convention. Consumers can add drivers through inherited `extend()` callbacks, which receive the Laravel container.

Each resolved driver is validated against `Contracts\Browser` and wrapped in an internal eventing decorator before it is memoized. This preserves the manager idiom and applies the visit lifecycle uniformly to built-in and application-registered drivers.

The configured default is `traverse.default`, defaulting to `lightpanda`. Until issue #3 implements it, the built-in Lightpanda driver fails fast with `Driver [lightpanda] is not available yet.`

### Public contracts

Every driver implements `Contracts\Browser`:

```php
public function visit(string $url): Page;
```

Every returned `Contracts\Page` implements the four V0.1 read primitives:

```php
public function markdown(): string;
public function semanticTree(): array;
public function interactiveElements(): array;
public function structuredData(): array;
```

`markdown()` returns text. Every structured primitive returns a plain, JSON-round-trippable array; public payloads must not contain objects, enums, or `stdClass` instances.

These four primitives are mandatory: they are Traverse's product, not optional automation features. Future optional behavior uses dedicated capability interfaces only when a real feature requires one. Examples include interaction, MCP, and CDP support; no speculative capability interface ships in V0.1.

### Visit lifecycle events

A visit made through `Contracts\Factory` has one invocation ID and dispatches `Events\VisitStarted` before the driver call, then exactly one terminal event: `Events\VisitCompleted` after a page is returned or `Events\VisitFailed` when the driver throws. The original driver exception is rethrown.

Events carry scalar operational metadata and timestamps. Completed events do not contain a `Page` or page content; failed events expose only the exception class, not diagnostic output. This keeps the events queue-serializable for custom drivers and prevents the package from making an unsafe content-delivery promise.

The internal decorator receives `Illuminate\Contracts\Events\Dispatcher` through the container. It does not use an event facade or helper, and events do not implement broadcasting or after-commit interfaces. Applications choose their own listeners, queues, transaction behavior, channels, authorization, and broadcast payloads.

### Configuration and service provider

`config/traverse.php` has a default driver and named driver arrays:

```php
return [
    'default' => env('TRAVERSE_DRIVER', 'lightpanda'),

    'drivers' => [
        'lightpanda' => [
            'driver' => 'lightpanda',
            'binary' => env('TRAVERSE_LIGHTPANDA_BINARY'),
            'timeout' => 30,
        ],
    ],
];
```

The service provider only merges this configuration and binds `Contracts\Factory` as a singleton `BrowserManager`. It has no facade, alias, routes, views, migrations, commands, or publishing surface at this stage.

Laravel 12's `mergeConfigFrom` only merges top-level keys. Driver implementations must therefore resolve their own nested defaults instead of depending on defaults in a published driver array.

### Laravel AI, MCP, and CDP boundaries

Laravel AI and Laravel MCP remain optional integrations, not core dependencies. Traverse core must never require `laravel/framework`, `laravel/ai`, or `laravel/mcp`.

AI tools, MCP tools, and CDP access are adapters over the browser abstraction. They do not shape the core contracts. `Ai\ReadPageTool` exposes one Laravel AI tool, `traverse-read`, which reads one URL as Markdown, a semantic tree, interactive elements, or structured data. It delegates to an internal page-reading action that uses only the browser contracts; it does not retain page state between tool calls or use Lightpanda APIs directly.

`Mcp\Tools\ReadPageTool` exposes the same `traverse-read` capability through Laravel MCP and delegates to that same page-reading action. `Mcp\TraverseServer` is a minimal server containing only this tool; applications explicitly register the transport and own its middleware, authorization, and egress policy. Kebab-case is Laravel MCP's default naming convention and is safe for the MCP tool-name character set. Dotted names are avoided for compatibility with strict MCP clients.

### Error policy

The core follows Laravel manager error semantics: unsupported drivers fail with `InvalidArgumentException`. Real driver-specific failures receive named exceptions only when real behavior exists.

## Consequences

- Issue #3 can implement `createLightpandaDriver()` without changing the public browser vocabulary.
- Issues #4 and #5 can build Laravel AI and MCP/CDP adapters over stable string and array payloads without coupling the core package to either pre-1.0 dependency.
- Custom machine-native drivers use the native Laravel `extend()` mechanism and receive the same visit lifecycle events when resolved through `Contracts\Factory`.
- Traverse deliberately does not provide browser automation, screenshots, PDFs, device emulation, stealth/proxy tooling, network interception, multi-tab orchestration, or a Chrome DevTools Protocol reimplementation.
- The V0.1 core has no facade. Applications depend on `Contracts\Factory` through constructor injection.
